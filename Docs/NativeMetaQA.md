# Native Meta dataset QA

The independent audit/compare program is maintained in `Build/Tests/Audit-NativeMeta.py`, with CLI usage in `Build/Tests/README.md`. It accepts all data/log/export/report/baseline paths and initial seed through arguments, uses Python's standard library, and can require actual complete-cohort evidence. The maintained program was run against the completed revision 3 baseline with a same-revision self comparison and `--require-complete`: 564,224 checks, zero failures. That adds one explicit completion gate to the 564,223-check historical audit below; it does not add a simulated match.

The completed datasets below were independently audited after actual persistence/export and clean exit. A subsequent replay regression found and corrected a floating-point post-payment residue (−4.66e−13 Aether), preserving the existing affordability tolerance and intended 0–10 bank bound. All36 portable scenarios, 21 complete seeded matches and nine UE integration tests pass with that correction. A fresh final-core10,000-match run is owned by the build pipeline; its completion and independent audit must be observed before claiming that newer executable's full cohort.

The saved dataset is independently checked against the captured 14-card roster, rule fingerprint and complete deterministic seed progression. The dataset is an aggregate of simulated generated decks, not a per-match snapshot archive. The worker validates each final bank/spend/leak budget and finite terminal state; the independent aggregate audit checks the retained totals and exported rows. Card/pair win rates describe associations within decks and opposing styles. Mirror exclusion helps interpretation but does not turn shared match/deck observations into independent card experiments; Wilson intervals are descriptive. Archetypes overlap, so their pick rates need not sum to 100%. Active simulation wall seconds omit pause/throttle waits and aggregation/JSON/persistence overhead; they do not measure frame rate, total elapsed runtime or player UI performance. Future runtime QA also supplies an isolated `-UserDir` for engine settings alongside the isolated `-RiftSaveRoot` for native profile/replay/dataset data.
