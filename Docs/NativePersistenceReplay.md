# Native persistence and replay contracts

The native profile is `%LOCALAPPDATA%/RiftCrownArena/ue_save.json`, with the existing command-line/environment save-root overrides retained. Native schema 1 can import valid browser `player_save.json` profile and five deck presets. Browser source files are preserved, their checksum is recorded, and unknown root/profile/preset/settings extension fields survive compatible native saves. Invalid preset cards cannot replace valid defaults, duplicate preset IDs use the first valid record, names are sanitized, counters saturate, and settings are normalized to finite supported values.

Writes create unique UTF-8 staging files, preserve the prior file as `.bak`, and use Windows `MoveFileExW` replacement with write-through. Recovery moves a corrupt primary into `Backups` before saving the recovered backup so a failed replacement cannot destroy the known-good backup. A future schema in either primary or backup disables profile writes and edits. Native profile reads are limited to 1 MB.

Native replay JSON schema 1 uses the `rift-native-1` model identity. Opening/importing first checks the entire recording: format/model, finite bounded duration, all snapshots, canonical card IDs, legal team/entity enums, complete hand/queue/deck shapes, finite numbers and bounded arrays, monotonic snapshot/event times, ordered event sequences, and valid result analysis. Invalid or future recordings leave the current replay and source file intact.

New native files use the `.riftreplay` extension and losslessly compressed condensed UTF-8 JSON. The 24-byte header is `RIFTREP1`, followed by four little-endian 32-bit values: decoded byte count, decoded CRC32, compressed byte count and compressed CRC32. Zlib data follows the header. Native archives are limited to 64 MB; decoded JSON and ordinary JSON input are limited to 256 MB. The reader sniffs a bounded header before allocating a full payload, checks supported magic/version and sizes, then verifies compressed and decoded checksums. Legacy JSON remains readable/importable, and Export produces ordinary JSON that can be reimported within the same decoded bound. No events, samples or fields are discarded. Profile filename normalization preserves both archive and legacy extensions.

Snapshots serialize all public native state, including AI observed cycles and decisions, card telemetry and its denominators, targeting/status ownership and timers, navigation/debug state, projectiles with damage/splash/cast attribution, and stationary hazards with cast/tick timing. Deserialization builds a temporary snapshot and commits only after successful validation. Optional new fields retain compatibility with earlier native format 1 recordings; unsupported browser replay archives remain preserved.

Each recorded sample bookmarks the latest observed event sequence. Playback starts from the latest sample at or before the requested time, applies later deploy/damage/status/phase/DEV events, advances resource and decay clocks, and interpolates entity positions toward the next sample or recorded death location. Dead entities remain at their recorded death position. This preserves immediate events between position samples without smearing card spending. Position interpolation is presentation; recorded native samples and events remain authoritative evidence. Forward playback broadcasts only newly crossed events through the regular match event delegate for VFX/audio; seeking rebuilds state and moves the cursor without replaying historical sounds. Event lookup uses a binary search from the sample bookmark, and interpolation indexes next-sample entity IDs rather than scanning them for every entity.
